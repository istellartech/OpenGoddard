速度 $u$ を直接操作して、位置 $x$ を距離 $d$ だけ動かします。「早く着きたい」と「操作量を小さくしたい」の
釣り合いで移動時間が決まります。`Problem` を組み立てる最小の手順を、解析解と照らし合わせて確認します。

## 問題

状態は位置 $x$、制御は $u$ です。時刻は $t_0 = 5$ から始まり、$t_f$ は自由です。既定値は $d = 2$ です。

$$
\dot{x} = u,\qquad x(t_0)=0,\quad x(t_f)=d,\qquad 0 \le u \le 3,\quad 5.1 \le t_f \le 15,\qquad
J = (t_f - t_0) + \int_{t_0}^{t_f} u^2\,dt
$$

同じ距離なら $\int u^2 dt$ は $u$ が一定のとき最小なので、$u = d/T$ とおくと $J = T + d^2/T$ です。
これを $T$ で最小化すると $T = d$、$u = 1$、$J = 2d$ になります。

## コードとの対応

| 数式 | `main.py` |
| --- | --- |
| $\dot{x}=u$ | `pointwise_dynamics` が `xp.stack((u[0],))` を返す |
| 境界条件 | `equality` の `result.equal(state[0], 0)`、`result.equal(state[-1], target)` |
| $0 \le u \le 3$、$5.1 \le t_f \le 15$ | `set_controls_bounds(0, 0, 0, 3)`、`set_time_final_bounds(0, 5.1, 15)` |
| $t_f - t_0$（終端項） | `problem.cost = LinearCallback(lambda p, obj: p.time_final(0) - p.time_start(0))` |
| $\int u^2 dt$（積分項） | `problem.running_cost = lambda p, obj: p.controls_all_section(0) ** 2` |
| 区間・ノード数・状態数・制御数 | `Problem([5, 8], [8], [1], [1], maxIterator=2)` |
| スケーリング | `set_unit_time(3)`、`set_unit_states(0, 0, 2)`（解は変えない） |

`running_cost` はノード上の被積分関数で、OpenGoddard がガウス求積で積分して `cost` に加えます。

## 結果

レール上を動く物体と、位置 $x$・制御 $u$ の時間履歴を解析解 $x = t - 5$、$u = 1$ と比べています。

<ExampleMedia id="minimum_energy_transfer" />

- 物体は $t = 5$ から $7$ までで移動し、所要時間 $T = 2$ は解析解 $T = d$ と一致します。
- $u$ は区間全体で 1 の一定値で、$x$ は直線的に増えます。目的関数は $J = 4$ です。
- $u$ の上限 3 も $t_f$ の上下限も効いておらず、時間と操作量の釣り合いだけで解が決まっています。

## 試す

<RunCommand id="minimum_energy_transfer" />

所要時間と目的関数を解析解と並べて表示します。

- `main()` の `target` を 3 に変えると、所要時間は 3、目的関数は 6 になるか。
- `set_controls_bounds` の上限を 0.5 に下げると $u = 1$ が許されず、$u = 0.5$、$T = 2d$ になるはず（最後の `assert_allclose` は失敗します）。
