[07. Goddard問題・単一区間](../07-goddard-0knot/) と同じ問題を、推進剤が尽きて推力がゼロになる
時刻で**2つの phase に分けて**解きます。phase どうしの境界を **knot**（結び目）と呼びます。
物理モデルと目的関数は 07 とまったく同じで、変わるのは「時間軸の分け方」と「境界のつなぎ方」だけです。

## この例題で学ぶこと

- knot とは何か、なぜ制御が切り替わる時刻に knot を置くと解がきれいになるのか
- `knot_states_smooth` による状態の連続条件と、制御を不連続にできること
- phase ごとに初期推定を変える方法と、knot 時刻への制約の掛け方

## 問題設定

状態 $h, v, m$、制御 $T$、運動方程式・境界条件・経路制約・目的関数は 07 と同じです。

$$
\dot{h} = v, \qquad
\dot{v} = \frac{T - D_c v^2 e^{-H_c (h - h_0)/h_0}}{m} - g_0\left(\frac{h_0}{h}\right)^2, \qquad
\dot{m} = -\frac{T}{c}, \qquad J = -h(t_f)
$$

違いは時間区間 $[0, t_f]$ を knot 時刻 $t_1$ で2つに分けることです。

$$
\text{phase 0}: [0, t_1], \qquad \text{phase 1}: [t_1, t_f]
$$

Goddard問題の最適推力は「最大推力 → 中間推力（特異弧） → 推力ゼロ」でした。
最後の切り替えでは推力が不連続に落ちます。擬スペクトル法は各 phase の中を1本の多項式で
近似するので、不連続を phase の**内部**に含むと 07 のように振動が出ます。
切り替え時刻を phase の**境界**に置けば、各 phase の中では推力が滑らかになり、
少ないノードで精度よく表せます。

knot では、物理的に飛び移れない状態量（位置・速度・質量）を連続させます。

$$
h(t_1^-) = h(t_1^+), \qquad v(t_1^-) = v(t_1^+), \qquad m(t_1^-) = m(t_1^+)
$$

一方、制御 $T$ には連続条件を課さないので、knot で推力は自由にジャンプできます。
このコードでは knot 時刻を $t_1 = 0.075$ に**固定**しています（07 の解で推進剤が尽きる時刻付近）。

## 数式とコードの対応

| 数式 | コード（`main.py`） |
| --- | --- |
| 2つの phase、初期の knot 時刻 0.1 | `time_init = [0.0, 0.1, 0.3]`, `n = [25, 25]` |
| 両 phase で同じ運動方程式 | `prob.dynamics = [dynamics, dynamics]` |
| knot での $h, v, m$ の連続 | `prob.knot_states_smooth = [True]` |
| $t_1 = 0.075$ | `equality` の `result.equal(ts0, 0.075)`（`ts0 = prob.time_final(0)`） |
| $t_1 \ge 0.05$ | `inequality` の `result.lower_bound(ts0, 0.05)` |
| 境界条件・経路制約 | 07 と同じ `result.equal(...)` / `lower_bound` / `upper_bound` |
| $J=-h(t_f)$ と勾配 | `cost` が `-h[-1]`、`cost_derivative` が終端高度の添字に `-prob.unit_states[-1][0]` を置く |
| 高度のスケーリング | `prob.set_unit_states_all_section(0, 0.1)` |

`knot_states_smooth` は knot ごとに `True` / `False` を並べたリストです。`True` の knot では、
ライブラリが「前の phase の最後のノード − 次の phase の最初のノード = 0」という等式制約を、
全状態について自動的に追加します（`Problem` の既定値はすべて `True`）。
制御には同様の条件を付けないため、推力は knot で不連続になれます。
時刻は `time_knots()` で phase の終端時刻を並べたものなので、knot 時刻自体は常に連続です。

初期推定も phase ごとに与えています。phase 0 は推力 3.5・質量 1.0 → 0.6、
phase 1 は推力 0・質量 0.6 で一定（`Guess.linear(prob.time[0], ...)` と `prob.time[1]`）とし、
`np.hstack` で連結しています。

## 計算結果

左は鉛直に上昇するロケット（▲）とオレンジの炎（相対的な推力）、右は速度・質量・推力です。
縦の点線が knot（$t_1 = 0.075$）、黒い縦線が動画の現在時刻です。
高度の変化は小さいため、左の場面は地面を描かずに縦軸を拡大しています。右の一番上のグラフが高度 $h$ の履歴です。

### 読み取りのポイント

- phase 0 の中で推力は $T_{\max} = 3.5$ から中間推力（約 2.1〜2.6）に下がり、knot の直前でまた上がります。
  knot で推力はほぼ 0 に**ジャンプ**し、phase 1 ではほぼ 0 のまま平らです。
  07 で見えた切り替え後の波打ちが消えていることを確かめてください。
- 質量は knot で約 0.6003 となり、phase 1 ではほぼ一定です。knot がちょうど推進剤切れの時刻に
  置かれているので、phase 1 は純粋な慣性上昇になります。
- 速度・質量のグラフは knot でつながっています（`knot_states_smooth = [True]` の効果）。
  速度は knot で折れ曲がりますが、これは加速度（=推力）が不連続なためで、速度自体は連続です。
- 最高高度は $h(t_f) \approx 1.0128$、$t_f \approx 0.200$ で、07 とほぼ同じ値になります。
  同じ問題を、半分のノード数の phase 2つでより滑らかに表現できています。

## 試してみる

<RunCommand id="goddard_1knot" />

`main.py` を次のように書き換えて違いを観察してみましょう。

- `result.equal(ts0, 0.075)` を `0.06` や `0.09` に変えると、knot が推進剤切れの時刻からずれます。
  推力の形と最高高度がどう変わるでしょうか。
- この等式を削除すると knot 時刻も最適化変数になります。`lower_bound(ts0, 0.05)` だけを残したとき、
  ソルバーが選ぶ $t_1$ はいくつになるでしょうか。
- `prob.knot_states_smooth = [False]` にすると、状態の連続条件が外れます。
  速度や質量が knot で飛ぶ、物理的に意味のない解が出ることを確認してみましょう。
