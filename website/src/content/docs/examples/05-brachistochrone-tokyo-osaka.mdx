東京から大阪まで約 600 km のトンネルを掘り、摩擦のない車両を重力だけで走らせるとします。
最も早く着くトンネルの形はどうなるでしょうか。03の最速降下を実寸のスケールに拡大し、
**終点を出発点と同じ高さ**に固定した問題です。物理量が $10^5$ m 単位になるため、
単位スケーリングの設定が欠かせない例題でもあります。

## この例題で学ぶこと

- 大きさの異なる状態量（数百 km の位置と km/s の速さ）を `set_unit_*` で揃える方法
- 終点の深さを固定した最速降下では、軌道が下りと上りの対称な形になること
- 旧来の関数形式（`Dynamics`・`Condition` を直接使う書き方）での問題定義

## 問題設定

状態と運動方程式は03と同じです。水平位置 $x$、深さ $y$（下向き正）、速さ $v$、
制御 $\theta$ は鉛直下向きから測った進行方向の角度です。

$$
\dot{x} = v\sin\theta, \qquad \dot{y} = v\cos\theta, \qquad \dot{v} = g\cos\theta
$$

`Ball` クラスの値は $g = 9.8$ m/s²、$l = 600\,000$ m です。重力は一様で鉛直下向きとし、
地球の曲率や重力方向の変化はコードに含まれていません。境界条件と制約は次のとおりです。

$$
x(0) = y(0) = v(0) = 0, \qquad x(t_f) = l, \qquad y(t_f) = 0,
$$

$$
0 \le x \le l, \qquad y \ge 0, \qquad 0 \le \theta \le \pi
$$

目的関数は到達時刻 $J = t_f$ です。終点の速さは指定しませんが、
摩擦がなく始点と同じ高さに戻るので、エネルギー保存から $v(t_f) = 0$ になります。

コードに解析解の比較はありませんが、この問題の解もサイクロイド
$x = a(\phi - \sin\phi)$、$y = a(1 - \cos\phi)$ になると考えられます。
同じ高さに戻る条件は $\phi = 2\pi$ にあたるので、$a = l/(2\pi) \approx 95.5$ km、
最大深さ $2a \approx 191$ km、到達時刻 $t_f = 2\pi\sqrt{a/g} \approx 620$ s が目安になります。

## 数式とコードの対応

| 数式 | コード（`main.py`） |
| --- | --- |
| $\dot{x}=v\sin\theta,\ \dot{y}=v\cos\theta,\ \dot{v}=g\cos\theta$ | `dynamics` の `dx[0] = v * np.sin(theta)`、`dx[1] = v * np.cos(theta)`、`dx[2] = g * np.cos(theta)` |
| $x(0)=y(0)=v(0)=0$ | `equality` の `result.equal(x[0], 0.0)` など3本 |
| $x(t_f)=l,\ y(t_f)=0$ | `result.equal(x[-1], obj.l)` と `result.equal(y[-1], 0.0)` |
| $0 \le x \le l$ | `inequality` の `result.lower_bound(x, 0)` と `result.upper_bound(x, obj.l)` |
| $y \ge 0$ | `result.lower_bound(y, 0)` |
| $0 \le \theta \le \pi$ | `result.lower_bound(theta, 0)` と `result.upper_bound(theta, np.pi)` |
| $J = t_f$ | `cost` が `prob.time_final(-1)` を返し、`cost_derivative` がその勾配を与える |
| 単位スケーリング | `unit_x = 300000`、`unit_y = 100000`、`unit_t = 100`、`unit_v = unit_x / unit_t` |
| ノード数・初期推定 | `n = [30]`、`time_init = [0.0, 600.0]`、$\theta$ は 0→$\pi$ の直線、$y$ は中央で `obj.h`（300 km）に達する山形 |
| 求解の設定 | `prob.solve(obj, display_func, maxiter=2000)` |

ソルバーは `x / unit_x` のような無次元量を扱います。600 km と数 km/s をそのまま並べると
変数の大きさが数桁違い、収束が悪くなるためです。`v_init` は計算されていますが
`set_states_all_section` に渡されていないため、速さの初期推定は既定値のままです。

`maxiter=2000` は SLSQP の反復上限です。既定の上限では途中で打ち切って再起動することになり、
そのたびに SLSQP が蓄えたヘッセ行列の推定が捨てられて収束が進みません。
上限を大きくして1回の長い実行にすると、1回の求解で収束します（`result.success` が `True`）。

## 計算結果

左はトンネル内を動く車両（点）の軌道で、横軸は水平距離 $x$（km）、縦軸は深さ（km、下向き）です。
左の図の右下にある `t =` は動画の現在時刻（s）です。右は速さ（km/s）と $\theta$（度）の時間履歴で、
黒い縦線と点が現在時刻の値を示します。

<ExampleMedia id="brachistochrone_tokyo_osaka" />

### 読み取りのポイント

- 軌道は中央付近で最も深くなるほぼ左右対称の形で、最大深さは約 189 km（$x \approx 285$ km 付近）です。
  サイクロイドから見積もった $2a \approx 191$ km に近い値です。
- 速さは最深部で最大の約 1.93 km/s になり、終点では再びほぼ 0 に戻ります。
  最大速度は、エネルギー保存 $v = \sqrt{2gy}$ で深さ 189 km から計算した値と一致します。
- $\theta$ はほぼ 0°（真下）から始まり、中央付近で 90°（水平）、終点でほぼ 180°（真上）まで、
  時間に対してほぼ直線的に増えます。曲線の小さな波は、30ノードの値を多項式で補間して描いているためです。
- 到達時刻は約 620.4 s（約10分）で、サイクロイドから見積もった約 620 s と合います。

## 試してみる

<RunCommand id="brachistochrone_tokyo_osaka" />

求解中は反復ごとに `tf` を表示し、求解後に図を表示して `output/` に保存します。
`main.py` の値を変えてみましょう。

- `Ball` の `l` を 400 km（`400000`）に変えると、最大深さと到達時刻はどう変わるでしょうか。
  サイクロイドの相似性から、深さは $l$ に比例し、時間は $\sqrt{l}$ に比例するはずです。
- `unit_x`・`unit_y`・`unit_t` をすべて 1 にすると、収束の様子はどう変わるでしょうか。スケーリングの効果を体感できます。
- `equality` のコメントアウトされた `result.equal(v[-1], 0.0)` は、エネルギー保存から自動的に満たされる条件です。
  有効にしても解そのものは変わらないはずですが、重複した条件が収束に影響しないか確かめてみましょう。
