電気推進のように推力が非常に小さい宇宙機で、半径 1 の円軌道から半径 4 の円軌道へ移ります。
推力が重力に比べて桁違いに小さいため、一度の噴射では軌道を変えられず、
中心天体の周りを回りながら少しずつ軌道を広げていくことになります。

## この例題で学ぶこと

- 重力定数と初期軌道半径を 1 とする無次元化
- 運動方程式に現れない角度 $\theta$ を状態から外し、計算後に積分して復元する方法
- 絶対値（L1ノルム）の目的関数を、非負の2変数に分けて滑らかな問題に書き換える方法

## 問題設定

重力定数 $\mu$ と初期半径を 1 とする無次元量で考えます。このとき初期円軌道の速度も 1、
時間の単位は「初期軌道を 1 rad 進む時間」です。状態は半径 $r$、半径方向速度 $v_r$、周方向速度 $v_t$ の3つで、
制御は推力加速度の各成分を**正の部分と負の部分に分けた** 4 つの変数 $u_{r1}, u_{r2}, u_{t1}, u_{t2}$ です。

$$
\dot{r} = v_r, \qquad
\dot{v}_r = \frac{v_t^2}{r} - \frac{1}{r^2} + (u_{r1} - u_{r2}), \qquad
\dot{v}_t = -\frac{v_r v_t}{r} + (u_{t1} - u_{t2})
$$

例題12の極座標の式から抗力と質量を除き、推力を加速度として直接与えた形です。
重力 $-1/r^2$ は $\mu = 1$ の逆二乗則です。

境界条件は、円軌道から円軌道への遷移を表します。半径 4 の円軌道速度は $\sqrt{1/4} = 0.5$ です。

$$
r(0) = 1,\ v_r(0) = 0,\ v_t(0) = 1; \qquad r(t_f) = 4,\ v_r(t_f) = 0,\ v_t(t_f) = 0.5
$$

不等式制約と目的関数は次のとおりです。終端時刻 $t_f$ は自由ですが、$0 \le t_f \le 55$ に制限されます。

$$
0 \le u_{r1}, u_{r2}, u_{t1}, u_{t2} \le 0.01, \qquad 1 \le r \le 4, \qquad
J = \int_0^{t_f} (u_{r1} + u_{r2} + u_{t1} + u_{t2})\,dt
$$

### なぜ制御を2つに分けるのか

推進剤の消費は推力の大きさに比例するので、本来は $\int (\lvert u_r\rvert + \lvert u_t\rvert)\,dt$ を最小化したいところです。
しかし $\lvert u\rvert$ は $u = 0$ で微分できず、勾配を使う SQP ソルバーには扱いにくい関数です。
そこで $u_r = u_{r1} - u_{r2}$（$u_{r1}, u_{r2} \ge 0$）と書き、$u_{r1} + u_{r2}$ を最小化します。
両方を同時に正にすると同じ $u_r$ を得るのにコストが余分にかかるので、最適解では片方が 0 になり、
$u_{r1} + u_{r2} = \lvert u_r\rvert$ が成り立ちます。こうして絶対値を、線形の目的関数と非負制約だけで表せます。
各成分の上限 0.01 は、推力加速度が初期軌道での重力加速度（1）の 1% であることを意味します。

### 角度 $\theta$ を状態に含めない理由

右辺には $\theta$ が現れません（中心力場は回転対称です）。そのため $\theta$ を状態に入れなくても問題は閉じており、
変数を減らせます。軌道の絵を描くときだけ、$\dot{\theta} = v_t / r$ を時間積分して角度を復元します。

## 数式とコードの対応

| 数式 | コード（`main.py`） |
| --- | --- |
| 無次元の境界値 | `Orbiter.__init__` の `self.r0 = 1.0`、`self.vt0 = 1.0`、`self.rf = 4.0`、`self.vtf = 0.5` |
| $\dot{r} = v_r$ | `dynamics` の `dx[0] = vr` |
| $\dot{v}_r$ | `dx[1] = vt**2 / r - 1 / r**2 + (ur1 - ur2)` |
| $\dot{v}_t$ | `dx[2] = -vr * vt / r + (ut1 - ut2)` |
| 初期・終端の円軌道 | `equality` の `result.equal(r[0], obj.r0)` 〜 `result.equal(vt[-1], obj.vtf)` の6本 |
| $0 \le u \le 0.01$ | `inequality` の `result.lower_bound(ur1, 0.0)`、`result.upper_bound(ur1, obj.u_max)` など |
| $1 \le r \le 4$ | `result.lower_bound(r, obj.r0)`、`result.upper_bound(r, obj.rf)` |
| $0 \le t_f \le 55$ | `result.lower_bound(tf, 0.0)`、`result.upper_bound(tf, obj.tf_max)` |
| $J = \int (u_{r1}+u_{r2}+u_{t1}+u_{t2})\,dt$ | `running_cost` が `(ur1 + ur2) + (ut1 + ut2)` を返し、`cost` は 0 |
| $\theta = \int v_t/r\,dt$ | `integrate.cumulative_trapezoid(vt / r, time, initial=0)` |

無次元化しているので、この例題では `set_unit_*` による単位設定は使っていません。
ノード数は `n = [60]` です。周回しながらゆっくり半径を広げる解は、時間方向に細かい構造を持つためです。
時刻の初期推定は `time_init = [0.0, 50.0]`、求解は `prob.solve(obj, display_func, ftol=1e-10, maxiter=300)` です。

### 初期推定の選び方

初期推定は次のとおりです。

| 変数 | 初期推定（`main.py`） |
| --- | --- |
| $r$ | `Guess.linear(prob.time_all_section, obj.r0, obj.rf)`（1 から 4 への直線） |
| $v_r$ | `Guess.linear(prob.time_all_section, obj.vr0, obj.vrf)`（0 のまま） |
| $v_t$ | `vt_init = 1 / np.sqrt(r_init)`（推定した半径での円軌道速度） |
| $u_{r1}$ | `Guess.constant(prob.time_all_section, 0.0)` |
| $u_{t1}$ | `Guess.constant(prob.time_all_section, obj.u_max / 2)` |

以前のコードは `time_init = [0.0, 10.0]` で、$u_{r1}, u_{t1}$ を上限 0.01 で一定にしていました。
この問題では速度を合計でおよそ $\Delta v \approx 0.5$ 変える必要がありますが、推力加速度の大きさは
$\sqrt{0.01^2 + 0.01^2} \approx 0.014$ 以下なので、少なくとも $t_f \gtrsim 35$ の時間がかかります。
$t_f = 10$ から出発した SLSQP は、線形化した制約を同時に満たす点を見つけられず、1回目の反復で
`Inequality constraints incompatible` を出して止まっていました。
現在は終端時刻の推定を最適解に近い 50 にし、$v_t$ を各半径での円軌道速度 $1/\sqrt{r}$ にして、
各時点で「ほぼ円軌道」の状態から出発するようにしています。非線形の問題では、物理的に筋の通った初期推定が収束を大きく左右します。

## 計算結果

左は軌道面の図です。中心の円が中心天体、破線の円が初期軌道（$r = 1$）と目標軌道（$r = 4$）です。
$\dot{\theta} = v_t/r$ を積分して復元した角度を使い $(r\cos\theta, r\sin\theta)$ を描き、
軌跡は噴射中をオレンジ、慣性飛行中を白で描きます。宇宙機の図は推力の向きに向け、オレンジの矢印で推力の向きを示します。
右は上から、軌道半径 $r$、周方向速度 $v_t$ と動径方向速度 $v_r$、周方向推力 $u_t = u_{t1} - u_{t2}$ と
動径方向推力 $u_r = u_{r1} - u_{r2}$ の時間履歴です（いずれも無次元）。灰色の斜線はエンジン停止（慣性飛行）の区間です。
左上の枠には時刻と $r, v_t, v_r$ の現在値を表示します。この例題では慣性飛行の区間も等速で再生し、最後の 1.5 秒は最終状態で止まります。

### 読み取りのポイント

- 最適化は収束し、終端時刻は上限の $t_f = 55$ に張り付きます。目的関数は $J \approx 0.579$ です。
  時間をかけるほど少ない推進剤で済むので、$t_f \le 55$ の制約が効いています。
- 軌道は中心天体の周りを約 3.8 周しながら、渦巻き状に半径 1 から 4 へ広がります。
- 推力の大部分は周方向で、$u_t$ はほぼ全区間で上限 0.01 に張り付いています。周方向に押し続けると軌道はゆっくり広がり、
  外側の円軌道ほど遅いので、加速を続けても $v_t$ は 1 から下がっていきます。
- $t \approx 44$〜48 では推力が 0 になり、慣性飛行します（左図の白い軌跡）。その前の $t \approx 36$〜41 では $u_r$ も上限まで使って外側へ押し出し、
  最後の $t \approx 48$〜55 では $u_t$ を上限で使いながら $u_r$ を $-0.01$ にして $v_r$ を 0 に戻し、$r = 4$、$v_t = 0.5$ の円軌道に入ります。
- 制御は上限 $\pm 0.01$ か 0 のどちらかを取る区間に分かれています。目的関数が L1 型（推力の絶対値の積分）であることの表れです。
  $u_r, u_t$ の切り替わり付近の小さな波打ちは、多項式近似による数値的な揺れです。

## 試してみる

`main.py` の値を書き換えて再実行し、変化を比べてみましょう。

- `time_init = [0.0, 50.0]` を以前の `[0.0, 10.0]` に戻したり、`vt_init` を `Guess.linear(prob.time_all_section, obj.vt0, obj.vtf)` に戻したりして、
  初期推定によって収束するかどうかが変わることを確かめてみましょう。
- `Orbiter.__init__` の `self.tf_max` を大きくすると、終端時刻と目的関数 $J$ はどう変わるでしょうか。
- `self.u_max = 0.01` を 0.05 などに大きくすると、周回数が減って遷移時間が短くなるはずです。必要に応じて `time_init` も短くしましょう。
- `self.rf = 4.0` を 2 にするときは、`self.vtf` を円軌道速度 $1/\sqrt{2}$ に合わせて変える必要があります。終端条件どうしの整合を考えてみましょう。
- `n = [60]` を増減させて、解の形と計算時間を比べてみましょう。
