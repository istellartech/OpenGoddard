電気推進のように推力が非常に小さい宇宙機で、半径 1 の円軌道から半径 4 の円軌道へ移ります。
推力が重力に比べて桁違いに小さいため、一度の噴射では軌道を変えられず、
中心天体の周りを回りながら少しずつ軌道を広げていくことになります。

## この例題で学ぶこと

- 重力定数と初期軌道半径を 1 とする無次元化
- 運動方程式に現れない角度 $\theta$ を状態から外し、計算後に積分して復元する方法
- 絶対値（L1ノルム）の目的関数を、非負の2変数に分けて滑らかな問題に書き換える方法

## 問題設定

重力定数 $\mu$ と初期半径を 1 とする無次元量で考えます。このとき初期円軌道の速度も 1、
時間の単位は「初期軌道を 1 rad 進む時間」です。状態は半径 $r$、半径方向速度 $v_r$、周方向速度 $v_t$ の3つで、
制御は推力加速度の各成分を**正の部分と負の部分に分けた** 4 つの変数 $u_{r1}, u_{r2}, u_{t1}, u_{t2}$ です。

$$
\dot{r} = v_r, \qquad
\dot{v}_r = \frac{v_t^2}{r} - \frac{1}{r^2} + (u_{r1} - u_{r2}), \qquad
\dot{v}_t = -\frac{v_r v_t}{r} + (u_{t1} - u_{t2})
$$

例題12の極座標の式から抗力と質量を除き、推力を加速度として直接与えた形です。
重力 $-1/r^2$ は $\mu = 1$ の逆二乗則です。

境界条件は、円軌道から円軌道への遷移を表します。半径 4 の円軌道速度は $\sqrt{1/4} = 0.5$ です。

$$
r(0) = 1,\ v_r(0) = 0,\ v_t(0) = 1; \qquad r(t_f) = 4,\ v_r(t_f) = 0,\ v_t(t_f) = 0.5
$$

不等式制約と目的関数は次のとおりです。終端時刻 $t_f$ は自由ですが、$0 \le t_f \le 55$ に制限されます。

$$
0 \le u_{r1}, u_{r2}, u_{t1}, u_{t2} \le 0.01, \qquad 1 \le r \le 4, \qquad
J = \int_0^{t_f} (u_{r1} + u_{r2} + u_{t1} + u_{t2})\,dt
$$

### なぜ制御を2つに分けるのか

推進剤の消費は推力の大きさに比例するので、本来は $\int (\lvert u_r\rvert + \lvert u_t\rvert)\,dt$ を最小化したいところです。
しかし $\lvert u\rvert$ は $u = 0$ で微分できず、勾配を使う SQP ソルバーには扱いにくい関数です。
そこで $u_r = u_{r1} - u_{r2}$（$u_{r1}, u_{r2} \ge 0$）と書き、$u_{r1} + u_{r2}$ を最小化します。
両方を同時に正にすると同じ $u_r$ を得るのにコストが余分にかかるので、最適解では片方が 0 になり、
$u_{r1} + u_{r2} = \lvert u_r\rvert$ が成り立ちます。こうして絶対値を、線形の目的関数と非負制約だけで表せます。
各成分の上限 0.01 は、推力加速度が初期軌道での重力加速度（1）の 1% であることを意味します。

### 角度 $\theta$ を状態に含めない理由

右辺には $\theta$ が現れません（中心力場は回転対称です）。そのため $\theta$ を状態に入れなくても問題は閉じており、
変数を減らせます。軌道の絵を描くときだけ、$\dot{\theta} = v_t / r$ を時間積分して角度を復元します。

## 数式とコードの対応

| 数式 | コード（`main.py`） |
| --- | --- |
| 無次元の境界値 | `Orbiter.__init__` の `self.r0 = 1.0`、`self.vt0 = 1.0`、`self.rf = 4.0`、`self.vtf = 0.5` |
| $\dot{r} = v_r$ | `dynamics` の `dx[0] = vr` |
| $\dot{v}_r$ | `dx[1] = vt**2 / r - 1 / r**2 + (ur1 - ur2)` |
| $\dot{v}_t$ | `dx[2] = -vr * vt / r + (ut1 - ut2)` |
| 初期・終端の円軌道 | `equality` の `result.equal(r[0], obj.r0)` 〜 `result.equal(vt[-1], obj.vtf)` の6本 |
| $0 \le u \le 0.01$ | `inequality` の `result.lower_bound(ur1, 0.0)`、`result.upper_bound(ur1, obj.u_max)` など |
| $1 \le r \le 4$ | `result.lower_bound(r, obj.r0)`、`result.upper_bound(r, obj.rf)` |
| $0 \le t_f \le 55$ | `result.lower_bound(tf, 0.0)`、`result.upper_bound(tf, obj.tf_max)` |
| $J = \int (u_{r1}+u_{r2}+u_{t1}+u_{t2})\,dt$ | `running_cost` が `(ur1 + ur2) + (ut1 + ut2)` を返し、`cost` は 0 |
| $\theta = \int v_t/r\,dt$ | `integrate.cumulative_trapezoid(vt / r, time, initial=0)` |

無次元化しているので、この例題では `set_unit_*` による単位設定は使っていません。
ノード数は `n = [100]` と多めです。周回しながらゆっくり半径を広げると予想される解は、時間方向に細かい構造を持つためです。
初期推定は $r, v_r, v_t$ を境界値の間の直線とし、$u_{r1}, u_{t1}$ を上限値 0.01 で一定にしています。

## 計算結果

**現在のコードでは、この例題の最適化は収束しません。** SLSQP は1回目の反復で
`Inequality constraints incompatible` を出して止まり、`main()` は初期推定をそのまま結果として返します。
以下の動画と図は最適解ではなく、この**初期推定**を描いたものです。

左は軌道面の図です。破線の円が半径 1 と 4 の円軌道、中心の点が中心天体で、
$\dot{\theta} = v_t/r$ を積分して復元した角度を使い $(r\cos\theta, r\sin\theta)$ を描いています。
右は半径 $r$、速度 $v_r, v_t$、推力成分 $u_r = u_{r1} - u_{r2}$ と $u_t = u_{t1} - u_{t2}$ の時間履歴です（いずれも無次元）。

<ExampleMedia id="low_thrust_orbit_transfer" />

### 読み取りのポイント

- 描かれているのは初期推定です。$t_f = 10$ のまま、$r$ は 1 から 4 へ直線、$v_r$ は常に 0、$v_t$ は 1 から 0.5 へ直線、$u_r, u_t$ は 0.01 で一定です。
- $v_r = 0$ なのに $r$ が増えているので $\dot{r} = v_r$ を満たしていません。運動方程式と矛盾するグラフは、収束していない解を見分ける手がかりになります。
- 収束した場合に期待される姿（未確認）：軌道は内側の円から外側の円へ渦巻き状に広がり、$v_t$ は 1 から 0.5 へ下がるはずです。外側の円軌道ほど遅いので、加速を続けても周方向速度は減ります。また L1 型の目的関数なので、$u_r, u_t$ は上限 $\pm 0.01$ か 0 のどちらかを取る区間に分かれやすいと考えられます。

## 試してみる

<RunCommand id="low_thrust_orbit_transfer" />

`main.py` の値を書き換えて再実行し、変化を比べてみましょう。

- `time_init = [0.0, 10.0]` の終端時刻の推定を 30 や 50 にすると、ソルバーの出発点が実現可能な解に近づくかを確かめてみましょう。上限 0.01 の推力で必要な速度変化を得るには、それなりの時間が必要です。
- `Orbiter.__init__` の `self.u_max = 0.01` を 0.05 などに大きくすると、（収束すれば）周回数が減って遷移時間が短くなるはずです。
- `self.rf = 4.0` を 2 にするときは、`self.vtf` を円軌道速度 $1/\sqrt{2}$ に合わせて変える必要があります。終端条件どうしの整合を考えてみましょう。
- `max_iteration = 10` を増やしたり `n = [100]` を減らしたりして、収束の様子と計算時間を比べてみましょう。
