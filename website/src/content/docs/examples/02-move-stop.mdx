レール上の物体を、静止状態から距離 $d$ だけ動かして再び止めます。
同じ運動方程式でも、**何を最小化するか**と**どの制約が効くか**で最適な加速度の形が
大きく変わることを確かめる例題です。

## この例題で学ぶこと

- 状態（位置・速度）と制御（加速度）の分け方
- 終端時刻を自由にする問題（最短時間）と固定する問題（最小二乗操作量）の書き分け
- 制御の上下限・速度上限が効くと解が「区間」に分かれること、区間を複数の phase で表す方法

## 問題設定

状態は位置 $x$ と速度 $v$、制御は加速度 $u$ です。

$$
\dot{x} = v, \qquad \dot{v} = u
$$

境界条件と制約は次のとおりです。

$$
x(0) = v(0) = 0, \qquad x(t_f) = d, \qquad v(t_f) = 0, \qquad
|u| \le a_{\max}, \qquad 0 \le v \le v_{\max}
$$

目的関数は `objective` パラメータで選びます。

| `objective` | 最小化するもの | 終端時刻 |
| --- | --- | --- |
| `minimum_time` | $J = t_f$ | 自由 |
| `minimum_effort` | $J = \displaystyle\int_0^{t_f} u^2\,dt$ | `duration` に固定 |

速度上限がない最短時間問題の解は「最大加速 → 最大減速」の bang-bang 制御で、
$t_f = 2\sqrt{d/a_{\max}}$ です。最小二乗操作量で上下限が効かない場合は、
加速度が時間の1次関数になり $J = 12d^2/t_f^3$ となります。
これらの解析解は `minimum_time()` と `phase_plan()` に実装され、数値解の検証に使われます。

## 数式とコードの対応

| 数式 | コード（`main.py`） |
| --- | --- |
| $\dot{x}=v,\ \dot{v}=u$ | `pointwise_dynamics` が `xp.stack((x[1], u[0]))` を返す |
| $x(0)=v(0)=0,\ x(t_f)=d,\ v(t_f)=0$ | `equality` の `c.equal(...)` 4本 |
| $\lvert u\rvert \le a_{\max}$ | `problem.set_controls_bounds(0, section, -a, a)` |
| $0 \le v \le v_{\max}$ | `problem.set_states_bounds(1, section, 0.0, p.speed_limit)` |
| $J=t_f$ | `problem.cost = LinearCallback(lambda prob, obj: prob.time_final(-1))` |
| $J=\int u^2 dt$ | `problem.running_cost = lambda prob, obj: prob.controls_all_section(0) ** 2` |
| $t_f$ 固定 | `problem.set_time_final_bounds(-1, p.duration, p.duration)` |
| 加速・定速・減速の区間 | `phase_plan()` が区間の数と初期推定を決め、各区間を1つの phase にする |

制御が不連続に切り替わる時刻を phase の境界に置くと、各 phase 内では制御が滑らかになり、
擬スペクトル法の多項式近似がよく効きます。境界時刻そのものも最適化変数です。
単位のスケーリング（`set_unit_time` など）は、ソルバーが扱う数値の大きさを揃えるためのものです。

### 読み取りのポイント

- `default`：加速度が $+a_{\max}$ から $-a_{\max}$ に一度だけ切り替わり、速度は三角形になります。
- `speed_limit`：速度が上限 2 m/s に達すると加速度 0 の定速区間（cruise）が現れ、速度は台形になります。
- `minimum_effort`：加速度は直線的に減少し、急な切り替えがありません。操作量の二乗積分を減らすためです。
- `limited_effort`：移動時間を短くすると、直線の両端が加速度上限で切り取られます。

## 試してみる

プリセットは `--preset`、個別のパラメータは `--set 名前=値` で変更できます。

<RunCommand id="move_stop" args="--preset speed_limit --plot" />
<RunCommand id="move_stop" args="--set distance=20 --set max_acceleration=1 --plot" />

- `duration` を短くしていくと、どこで加速度上限に達するでしょうか。最短時間より短くするとエラーになる理由を考えてみましょう。
- `speed_limit` を `null` にした最短時間解と比べ、移動時間はどれだけ延びるでしょうか。
